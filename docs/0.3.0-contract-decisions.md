## D02 lifetime/resource table to complete

The table is a compatibility constraint/template, not proof of current implementation correctness. The final record must list timers, retry work, detection subscriptions/traps/polls and abort listeners separately. Hooks now receive private lifecycle updates; they do not install global ww event listeners. Caller-installed diagnostic listeners have their own cleanup. A shared root resource ends only when no live subscriber needs it.

| Trigger | Persistent watchWindot | waitForWindot | useWatchWindot |
|---|---|---|---|
| Successful delivery | Keep detection and needed abort listener; end completed timeout/retry work per recorded policy | Settle once; release all resources owned by this wait | Follow watcher lifetime; define UI status/reset under D06 |
| Initial timeout with retries left | Report timeout/start selected retry work; retain late-readiness detection | Follow selected retry policy; release completed attempt resources | Follow watch; timeout does not silently destroy effect |
| Final timeout / retry exhaustion | End timeout/retry work; retain subscription, required detection and abort listener for late readiness | Reject once; release all resources owned by this wait | Follow watch while mounted; late readiness remains possible |
| once delivery | End watcher resources even on callback throw/reentrancy | Already terminal after resolution | Follow once; mounted React state remains until effect cleanup or replacement |
| Abort | End watcher resources | Reject with exact supported reason; release all wait resources | End detection; private observer clears value/error and sets idle |
| Explicit dispose / unmount | End watcher resources idempotently | Define supported cancellation entry point and settlement; do not invent a promise dispose API | End effect resources; no stale state update |
| Setup failure | Roll back every acquired resource without disturbing other subscribers | Reject/throw as documented, with complete rollback | Registration rollback releases acquired resources even when the effect has no disposer; report the setup error |

Any departure from persistent callback success/timeout lifetime needs explicit compatibility evidence, accepted migration and updated docs. Test callback timeout then readiness **after retry exhaustion** alongside terminal promise cleanup, including pure polling.

## Accepted execution choices and tooling discovery

On 2026-10-02 the user answered “agreed” to persistent enabled snapshot checks until disposal and rejection of poll/interception root sharing, with auto/proxy sharing allowed. D03 records those accepted choices. Codex is the implementation/integration owner under “let’s get to work”; other provisional choices are implementation judgments, not claims that the user separately accepted every proposal.

Current runtime choices: distinct intercepted writes preserve occurrences; equal poll snapshots suppress duplicates until a readiness transition; readiness is rechecked around event reentrancy. Persistent callbacks outlive timeout/retry exhaustion, while waits clean up on terminal outcomes. Detection failures report the first error per subscription episode; successful checks reset it. Hooks use private identity, update predicates in place, clear values on observed invalidation/error, and become idle after abort. Numeric domains are finite delays/integer retries from zero through 2,147,483,647, fractions rounded up for cancellable timers. Manual timer/listener composition is deliberate so setup validation and cleanup do not depend on uncancellable native timeout signals. Exact trace/resource/migration rows remain in progress until full evidence is recorded.

The user explicitly selected “kill CommonJS” and modern ESM/Bun/Vite/Vitest tooling, then requested ruthless complexity removal “without obviously breaking things.” D10 therefore authorizes the package-format break, not arbitrary regressions in retained APIs. CommonJS and mixed-format acceptance requirements are superseded by an ESM-only migration disposition; their historical findings remain evidence. Core and React import one shared chunk, without a global symbol or build fingerprint. Bun owns installs, files, processes, hashing and static servers; Vite owns library/example bundling; native TypeScript emits declarations; Vitest retains behavior coverage in actual browsers. Duplicate internal one-shot polling and write-only delivery caches are removed. Small optional-platform guards remain where they protect retained disposal/abort behavior.

Latest stable direct dependencies were queried on 2026-10-02, including React/React DOM 19.3.0, Bun 1.4.2, Vite 8.3.2, Vitest 5.0.3, TypeScript 7.0.2 and Playwright 1.63.0. [React 19.3](https://react.dev/blog/2026/09/09/react-19-3), [Bun APIs](https://bun.sh/docs/runtime/nodejs-compat), [Vite library builds](https://vite.dev/guide/build.html#library-mode) and [Vitest browser mode](https://vitest.dev/guide/browser/) establish tooling intent; actual installed checks establish compatibility. Existing Node/React minima remain verification requirements, not silently raised ranges. The macOS 14 WebKit binary is frozen and fails the current Playwright page protocol; WebKit remains required on a supported Linux CI host. No automatic Node runtime fallback is introduced.
