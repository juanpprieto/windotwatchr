### Compatibility evidence to carry into migration decisions

| Change from 0.2.0 | Classification | Consumer consequence |
|---|---|---|
| Predicates applied to trap/proxy deliveries | Intentional behavior correction with compatibility impact | Callbacks previously receiving values rejected by their predicate stop receiving them |
| `strategy` starts affecting detection | Intentional behavior change to previously ignored option | Existing explicit proxy/poll callers change behavior; mixed strategies also have defects below |
| Timeout/abort rejections change | Intentional breaking error contract | Error names/messages/types and arbitrary abort reasons require different catch handling |
| `once`, correlation IDs, explicit disposal, event types | Intended additive features | Additions require correct cleanup, packaging, and runtime support |
| Same-value callbacks suppressed across subscription lifetime | Undocumented breaking change | Reassignment of the same value/object no longer reliably triggers persistent consumers |
| `ww:ready` becomes one event per subscriber | Undocumented breaking change | Two subscribers produce two global events instead of one; analytics/initialization listeners can duplicate work |
| Public return type requires global `Disposable` | Unintended source incompatibility | Ordinary consumer TypeScript builds fail |
| Restoring a pre-existing SDK preserves its Proxy | Unintended identity regression | SDK identity differs even after the last watcher disposes |
| Native timeout validates numbers differently | Unintended runtime incompatibility | Fractional numeric timeouts can reject immediately and leave watchers installed |
| Hook ignores uncorrelated poll errors | Incomplete event migration | A watcher can emit errors without its hook reporting error status |

The numeric pre-1.0 bump does not establish backward compatibility. T01/T19 must describe accepted breaks explicitly; a changeset minor describes the numeric increment. Primary references for that decision: [SemVer initial development](https://semver.org/spec/v2.0.0.html) and [npm semver caret ranges](https://github.com/npm/node-semver#caret-ranges-123-025-004). No API choice is approved by this evidence table.
