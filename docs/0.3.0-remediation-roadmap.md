**Target:** a documented breaking pre-1.0 release that fixes the confirmed regressions, fulfills the remaining 0.3.0 commitments, and accurately describes its limits. `0.3.0` remains the proposed version; a Changesets `minor` entry describes the numeric bump, not a claim of backward compatibility.

This roadmap defines remaining work. Tasks start **open** and move through criterion-level evidence, including verification of previously implemented features. Existing passing tests are baseline evidence, not closure of the new acceptance criteria. Implementation started on 2026-10-02; publication remains a separately authorized stage. There are **27 release tasks, 180 seeded criterion rows, and 7 future task cards**. The [decision record](./0.3.0-contract-decisions.md) and [criterion ledger](./0.3.0-validation-ledger.md) are required planning artifacts, with decisions and criteria tracked separately as execution progresses. Updating the plan does not approve a proposed API policy or establish that any defect has been fixed.

## Dependency and tooling deliverables added during execution

The user requested latest key dependencies/React, then explicitly selected ESM-only exports and Bun/Vite/Vitest tooling. This authorizes CommonJS removal as a documented breaking change. Subsequent instructions require removing unused/duplicate/legacy complexity while preserving retained behavior. Bun-native APIs belong in tooling; the browser package stays runtime-independent.

- [Refresh key dependencies and verify the latest React](./0.3.0-remediation-tasks.md#t26): inventory exact registry versions, migrate major upgrades, update manifests/lockfile and rerun latest/minimum consumer and browser gates.
- [Adopt Bun/Vite/Vitest and ESM-only packaging](./0.3.0-remediation-tasks.md#t27): remove dual-format ownership, obsolete tooling and duplicate polling; verify the selected path with strict packed ESM consumers, production examples and native browser regressions.

Both deliverables gate final candidate preparation. Prior CommonJS criteria retain their IDs/history but are explicitly superseded under D10; retained behavior requirements remain required. Dependency/build changes invalidate affected evidence and final sign-off.

## Evidence and closure rules

The [criterion ledger](./0.3.0-validation-ledger.md) owns closure, with stable IDs for each named subfinding/minor/inherited case/original unmet commitment. T02 establishes it before implementation. Each row records expected behavior, owner, decision dependency, baseline classification, named automated test/command and result, manual UAT environment/result, status and durable evidence links. Expand grouped matrix/input/shape rows into exact stable child cases before execution; a parent requires all its required children. Keep red characterization evidence separate from green candidate acceptance. Temporary `/tmp` probes and earlier green suites cannot establish closure.

Use statuses `open`, `in progress`, `blocked`, `verified` and `deferred`. Task verification requires every required row/child and UAT evidence; a qualification/skip requires reason, scope decision and shipped limitation, not a fabricated pass. Release-required work cannot be counted complete by relabeling it deferred. New findings reopen owning rows. Any accepted scope/contract change updates decisions, ledger and public docs together.

Pre-release gates are mandatory: all required T01–T22 rows closed; T25 produces the final versioned candidate and exact-SHA gates; T23 approves that exact SHA/tarball digest independently. Record the earlier source-input SHA separately. Any release-content/build-input change invalidates affected checks and sign-off and returns to T25/T23. T24 publishes only the verified artifact or a rebuild with proven digest equivalence, after separate authorization. Post-publication registry/Pages outcomes are recorded afterward and cannot substitute for pre-release evidence.

Existing baseline commands, run from the repository root against fresh candidate outputs:

```sh
bun run check
bun run build
bun run --cwd examples/nextjs build
bun run --cwd examples/vite-react build
bun run test:e2e -- --reporter=line --workers=2
```

These commands cover the existing gates only. T03/T16 add packed-consumer and compiled-using checks; T20/T21 expand browser/UAT coverage; T18 adds measurements. T22 makes the complete set reproducible in CI. Record the actual commands for those additions in the evidence manifest rather than assuming the baseline commands cover them.
